## Open handover gaps found

1. The two public “photo upload” areas are still visual controls only. The browser found zero public file inputs, so estimate/query photos are not submitted. Enabling this safely needs a public-upload security design (rate limiting/abuse protection, file validation, a separate upload path, and cleanup behavior) in the hardening step.
2. The locked Admin dashboard shows Query and Estimate totals, but the locked interface has no list/detail screen for reading those submissions. The records are stored correctly in Supabase. Handover must either document Supabase Table Editor as the reading workflow or approve a future interface change.
3. “Unlimited slots” means the code adds a slot for every uploaded image and has no fixed UI/database slot limit. Real usage is still bounded by browser memory, the 10 MB per-file validation, and the Cloudinary account quota.

## Test support added

- `tests/e2e/mock-service.mjs` provides reusable, isolated Supabase/Auth/PostgREST/Cloudinary behavior for browser tests.
- `VITE_CLOUDINARY_API_BASE` is optional and used only by isolated tests; production continues to default to `https://api.cloudinary.com`.
- `E2E_MOCK_API_URL` optionally enables the Vite `/api` proxy for isolated tests; production build behavior is unchanged.
